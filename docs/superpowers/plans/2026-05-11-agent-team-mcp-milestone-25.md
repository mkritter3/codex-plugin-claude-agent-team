# Agent Team MCP Milestone 25 Parallel Agent Start Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a first-class MCP tool that starts multiple durable agent sessions in parallel with bounded concurrency.

**Architecture:** `agent_team_start_parallel` is a start-family MCP tool over the existing lifecycle manager, not a hidden mode on synchronous dispatch. Each child agent still uses the normal `AgentLifecycleManager.startRun` path, writes its own sidecar/mailboxes/logs, and remains individually addressable by `agent_team_status`, `agent_team_message`, `agent_team_wind_down`, `agent_team_cancel`, and `agent_team_cleanup`. The tool returns partial-success evidence and does not aggregate model quality, synthesize verdicts, add providers, or bypass Claude Code CLI subscription OAuth.

**Tech Stack:** TypeScript, Node.js ESM, Vitest, MCP Zod schemas, provider-neutral lifecycle manager, durable run sidecars and mailboxes.

## Success Criteria

- `agent_team_start_parallel` appears in `listToolNames()` and MCP metadata.
- Input shape is `{ runs: [{ role, task, cwd?, provider?, timeoutMs?, correlationId? }], cwd?, provider?, timeoutMs?, concurrency? }`.
- Top-level `cwd`, `provider`, and `timeoutMs` apply as defaults for child runs; child values override defaults.
- `runs` must be a non-empty array.
- `concurrency` must be a positive integer from 1 through 8; default is 3.
- The helper starts at most `concurrency` child runs at the same time.
- Results preserve input order, including failures.
- One child failure does not prevent later queued children from starting.
- Each successful child is the exact `AgentStartResult` returned by the lifecycle manager plus `index` and optional `correlationId`.
- Each failed child returns index, optional correlation id, role, task, status `failed`, and an error message without inventing a sidecar.
- The tool returns `status: "started"` when all children start and `status: "partial_failure"` when any child fails.
- The tool returns a `batchId` generated by the caller/tool layer for correlation; it is not a durable batch sidecar in this milestone.
- The tool uses the same workspace config and lifecycle registry behavior as `agent_team_start`.
- Sidecars, mailboxes, verdicts, status, wind-down, and cleanup remain first-class per child run.
- Claude Code CLI subscription OAuth remains the primary v1 transport.
- No API-key fallback, heuristic/mock LLM behavior, benchmark claim, provider-specific MCP schema, provider runtime implementation, aggregate model-quality verdict, implicit batch cancellation, or automatic workspace deletion is introduced.
- `npm run typecheck`, `npm test`, `npm run build`, `npm run smoke:mcp-stdio`, and `npm run ci` pass in the implementation worktree before merge.

```ts
export interface AgentParallelStartRun {
  readonly role: RoleId;
  readonly task: string;
  readonly cwd: string;
  readonly provider?: string;
  readonly timeoutMs?: number;
  readonly correlationId?: string;
}

export interface AgentParallelStartRequest {
  readonly batchId: string;
  readonly runs: readonly AgentParallelStartRun[];
  readonly concurrency: number;
}

export interface AgentParallelStartSuccess {
  readonly status: "started";
  readonly index: number;
  readonly correlationId?: string;
  readonly run: AgentStartResult;
}

export interface AgentParallelStartFailure {
  readonly status: "failed";
  readonly index: number;
  readonly correlationId?: string;
  readonly role: RoleId;
  readonly task: string;
  readonly error: string;
}

export type AgentParallelStartRunResult =
  | AgentParallelStartSuccess
  | AgentParallelStartFailure;

export interface AgentParallelStartResult {
  readonly status: "started" | "partial_failure";
  readonly batchId: string;
  readonly concurrency: number;
  readonly runs: readonly AgentParallelStartRunResult[];
}
```

- [ ] **Step 3: Implement bounded launcher**

In `src/core/parallel-start.ts`, export:

```ts
export interface ParallelStartDependencies {
  readonly startRun: (request: AgentDispatchRequest) => Promise<AgentStartResult>;
}

export async function startAgentTeamInParallel(
  request: AgentParallelStartRequest,
  deps: ParallelStartDependencies
): Promise<AgentParallelStartResult>
```

Implementation requirements:

- allocate a fixed result array with the same length as `request.runs`
- run a worker loop with `Math.min(request.concurrency, request.runs.length)` workers
- each worker claims the next index synchronously before awaiting `deps.startRun`
- call `deps.startRun` with `{ role, task, cwd, provider?, timeoutMs? }`
- map successes to `{ status: "started", index, correlationId?, run }`
- map thrown errors to `{ status: "failed", index, correlationId?, role, task, error }`
- return `partial_failure` when any child result has `status: "failed"`
